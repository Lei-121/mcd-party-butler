# 麦当劳派对预约 · 接口链路参考

本文件是 `SKILL.md` 的配套参考，包含各步骤的完整入参、返回字段含义、实测样本数据与错误处理。

> **数据来源**：全部字段名与样本数据来自真实调用，实测时间 2026-10-10，城市深圳。价格、场次、余位会随时间变化，样本仅用于理解结构与单位。

## 一、工具名称对照

本技能使用以下麦当劳 MCP 工具（文中使用简称，实际调用需加 `mcp__mcd-mcp__` 前缀）：

| 简称 | 完整工具名 | 作用 |

| `mall-points-products` | `mcp__mcd-mcp__mall-points-products` | 查可预约的派对商品列表 |

## 二、派对类目编码

`mall-points-products` 的 `catRuleIds` 参数支持以下派对类目：

| 编码 | 类目 |
|---|---|
| `1>6>20` | 生日类派对 |
| `1>6>21` | 主题类派对 |
| `1>6>22` | 麦麦体验营 |
| `1>6>25` | 品鉴会 |
| `1>6>34` | 读书会 |

多个类目用英文逗号分隔。派对类商品全部为 `shopId=5`，这是 `party-order-create` 的前置条件。

## 三、逐级调用说明

### ① 查商品列表 — `mall-points-products`

```
入参：
  catRuleIds = "1>6>20,1>6>21,1>6>22,1>6>25,1>6>34"

关键返回字段：
  spuId      商品ID，后续所有步骤都要用
  spuName    商品名称
  price      所需金额（元）
  point      所需积分
  shopId     店铺ID，派对类固定为 5
  catName    所属类目名称
  status     1仓库中 / 2上架 / 3售罄 / 4下架 / 5预热 —— 只推荐 status=2
  selling    卖点文案
  upTime     兑换起始时间
  downTime   兑换截止时间 —— 已过期的商品应剔除

⚠️ **该接口不返回任何派对属性**：`partyAge`、`partyType`、`partyPeople`、`partyRange` **均不在返回中**。因此"按年龄筛选"不可能在这一步完成，详见下文 ②·补 的字段对照表。
```

### ② 查商品详情 — `mall-product-detail`

```
入参：
  spuId = 6370

关键返回字段：
  skuId            下单必传，从 skuList 中取
  skuList[].price  该 SKU 所需金额
  spuCategory      "1"虚拟商品 / "2"实体物品，派对类为 "1"
  partyType        1=仅包场 / 2=仅拼团 / -1=包场和拼团都支持
  partyPeople      人数范围，如 "5-12"
  partyAge         适合年龄，如 "4-12"
  partyRange       派对时长，以半小时为单位，如 3 表示 90 分钟
  note             购买须知长文（HTML），关键规则都在这里
  shopId           派对类固定为 5
```

**注意三个必须处理的点**：

1. **`partyType=-1` 时必须问用户**选包场还是拼团，不能替他决定。
2. **`note` 是 HTML 长文**，需要从中提炼关键规则后以人话转述，但**不得提取其中数值用于前置校验**。
3. `partyRange=3` 表示 90 分钟，展示时要换算成分钟或小时。

**实测样本**（麦当劳过家家派对）：
- `skuId` = 6912，价格 55 元
- `partyType` = -1（两种模式都支持，必须问用户）
- `partyPeople` = "5-12"
- `partyAge` = "4-12"
- `partyRange` = 3（即 90 分钟）
- `note` 中的关键规则：需提前 3 天预订；拼团需超过 5 位儿童才可举办，未成团则自动取消并退款；包场需 5 位儿童起订，每增加一位按单价递增，上限 12 位；退订需提前 3 天，活动当天缺席费用不退；仅中国内地门店适用。

**跨商品属性对比实测**（2026-10-10，验证年龄与人数确实存在商品间差异）：

| 商品 | spuId | partyAge | partyPeople | partyType | partyRange |
|---|---|---|---|---|---|
| 麦当劳亲子读书会 | 1830 | 4-12 | 5-12 | -1 | 3（90 分钟） |
| 四小福永远好朋友派对豪华版 | 3087 | 4-12 | 5-12 | -1 | 4（120 分钟） |
| 开心特工派对之深海探秘 | 6971 | **3-11** | **10-50** | -1 | 3（90 分钟） |
| 一年一度品虾会 | 15146 | — | — | — | 详情返回 `610403 商品已下架` |

年龄区间（3-11 / 4-12）与人数组距（5-12 / 10-50）在商品间差异明显——**说明按年龄筛选是有效的**，但前提是必须先查到详情。

### ②·补 列表层 vs 详情层：字段可得性对照

**这是本链路最容易踩的设计陷阱**：年龄与派对属性都在详情层，列表层一个都拿不到。

| 字段 | 含义 | 列表接口 | 详情接口 |
|---|---|---|---|
| `catName` | 类目 | ✅ | ✅ |
| `spuName` | 名称 | ✅ | ✅ |
| `price` | 价格 | ✅ | ✅ |
| `status` | 状态 | ✅ | — |
| `upTime` / `downTime` | 兑换有效期 | ✅ | ✅ |
| `skuId` | 下单必传 | ❌ | ✅ |
| `partyAge` | 适合年龄 | ❌ | ✅ |
| `partyPeople` | 人数范围 | ❌ | ✅ |
| `partyType` | 成团方式 | ❌ | ✅ |
| `partyRange` | 时长 | ❌ | ✅ |
| `note` | 须知长文 | ❌ | ✅ |

**结论：筛选必须两段式**——列表层粗筛（类目 / 名称 / 价格 / 有效期 / 状态）→ 详情层精筛（年龄 / 人数 / 模式 / 时长）。试图在列表阶段按年龄过滤，逻辑上无法执行。

⚠️ **另有一条实测异常**：**列表 `status=2` 与详情可售状态可能不一致**。商品 `15146`「一年一度品虾会」在列表中 `status=2`（上架），调详情却返回 `code=610403 商品已下架`。**不能仅凭列表状态判定可售**，必须以详情接口返回为准。

### ③ 查城市 — `query-party-city`

```
入参：
  spuId = 6370

关键返回字段：
  code       城市编码，下一步必传
  name       城市名称
  latitude   纬度，下一步必传
  longitude  经度，下一步必传
  initial    首字母，可用于快速匹配
```

**实测结果**：返回 300 多个城市。深圳为 `code=440300`，`latitude=22.543527`，`longitude=114.057939`。

⚠️ 返回列表很长，只展示与用户输入匹配的城市，不要罗列全表。

### ④ 查门店 — `query-party-store`

```
入参：
  code      = "440300"
  latitude  = 22.543527
  longitude = 114.057939
  spuId     = 6370

关键返回字段：
  code            门店编码，下一步必传
  name            门店名称
  address         门店地址
  distance        距离（米）
  distanceText    距离文本，如 "2.1km"
  businessStatus  营业状态
```

**实测结果**：深圳为 `code=440300`，`latitude=22.543527`，`longitude=114.057939`。

⚠️ **必须按 `distance` 排序后只展示前 3–5 家，并交代总数。**

⚠️⚠️ **门店列表是「商品 × 城市」维度的结果，不是城市的固有属性。** 实测同一城市下，不同派对商品返回的门店集合完全不同：

| 商品 | 深圳可办门店数 | 最近门店 |
|---|---|---|
| 麦当劳过家家派对（spuId=6370） | **54 家** | 皇岗村餐厅（`1420194`，2.1km） |
| 麦当劳奇妙生日派对（spuId=1779） | **32 家** | 龙悦居餐厅（`1420327`，7.2km） |

且 `1420194` **不在** 1779 的门店名单中——对它调用 `query-party-store-date` 会返回空数组。

**结论：换商品必须重新执行第 2–3 步，禁止复用门店编码。**

### ⑤ 查可约日期 — `query-party-store-date`

```
入参：
  storeCode = "1420194"
  spuId     = 6370

关键返回字段：
  date   可预约日期，下一步必传
```

**实测结果**：同一城市、不同门店、不同商品，可约日期差异极大：

| 商品 | 门店 | 可约日期 | 天数 |
|---|---|---|---|
| 过家家派对（6370） | 皇岗村（1420194） | 2026-10-17 ~ 10-19 | **3 天** |
| 奇妙生日派对（1779） | 龙悦居（1420327） | 2026-10-11 ~ 10-19 | **9 天** |
| 奇妙生日派对（1779） | 皇岗村（1420194） | — | **0 天（空）** |

⚠️ **这是"先查后问"原则的由来。** 实测中可约日期远少于用户的直觉预期（实测当天 10-10，某些门店最早可约已是 10-17），若先问用户日期再查，大概率会让用户期待落空。

⚠️ **若返回空数组**，说明该门店不支持当前商品（而非"当天没有排期"），应向用户说明并回到第 3 步换门店。


**实测结果**：

奇妙生日派对（1779）· 龙悦居（1420327）· 2026-10-17：

| id | 时间段 | partyMin | partyMax | price（分） | 折合 | leftNum |

### ⑦ 创建订单 — `party-order-create`

```
必传入参：
  partyType   1=包场 / 2=拼团（商品 partyType=-1 时须由用户确认）
  spuId       商品ID
  skuId       SKU ID
  code        城市编码
  storeCode   门店编码
  dateStr     门店日期
  id          场次ID
  timeStart   场次开始时间
  timeEnd     场次结束时间
  leftNum     场次余位（取自场次查询结果）
  count       参与人数

前提条件：
  仅支持 shopId=5 的商品
  每一步完成后必须等待用户明确选择，不得跳步
```

⚠️ **调用前必须完成二次确认**，向用户完整列出门店、日期、场次、人数、模式、总价与风险提示。

## 四、错误处理

| 情况 | 处理方式 |
|---|---|
| `query-party-city` 返回为空 | 说明该商品暂无可办城市，建议换一个派对商品 |
| `query-party-store` 返回为空 | 说明该商品在该城市暂无可办门店，建议换邻近城市 |
| `query-party-store-date` 返回为空 | **该门店不支持当前商品**（常见于跨商品复用了门店编码）。应回到第 3 步重新查门店，而不是让用户换日期 |
| `query-party-store-session` 返回为空 | 该日无排期，建议换日期 |
| 所有场次 `leftNum=0` | 该日已满，建议换日期或门店 |
| `mall-product-detail` 返回 `610403 商品已下架` | 该商品在列表里可能仍显示 `status=2`。直接剔除该商品，改用其他候选 |
| 下单返回失败 | 直接把接口返回的失败原因原样展示给用户，不要自行改写或猜测 |

## 五、完整调用序列（示例）

```
mall-points-products(catRuleIds="1>6>20,1>6>21,1>6>22,1>6>25,1>6>34")
  → 【列表层粗筛】按类目 / 名称 / 价格 / 有效期收敛到 5-8 个候选
  → 注意：此处拿不到 partyAge，禁止在这一步做年龄过滤
  → 用户选 spuId=6370
mall-product-detail(spuId=6370)
  → 【详情层精筛】得到 partyAge="4-12" 用于年龄筛选
  → 同时得到 skuId=6912, partyType=-1, partyPeople="5-12"
  → 用户确认城市：深圳市
query-party-city(spuId=6370)
  → code=440300, latitude=22.543527, longitude=114.057939
query-party-store(code="440300", latitude=22.543527, longitude=114.057939, spuId=6370)
  → 54 家门店铺，用户选 code=1420194
query-party-store-date(storeCode="1420194", spuId=6370)
  → 可约 2026-10-17 / 10-18 / 10-19，用户选 2026-10-17
query-party-store-session(storeCode="1420194", dateStr="2026-10-17", spuId=6370)
  → id=36926509, 15:30-17:00, price=5500, leftNum=12
  → 用户确认：包场，6 人
[二次确认后]
party-order-create(partyType=1, spuId=6370, skuId=6912, code="440300",
                   storeCode="1420194", dateStr="2026-10-17",
                   id=36926509, timeStart="15:30", timeEnd="17:00",
                   leftNum=12, count=6)
```
